# 会话记忆

本项目的记忆以同一用户的 `session_id` 为单位。新建对话有独立上下文；不会把另一会话的订单、摘要或待处理诉求自动带进来。

## 直接体验

重启后端并刷新页面，在同一个对话中依次输入：

1. `我要把马克杯退掉，太丑了` → 提示补订单号。
2. `ORD10002` → 沿用上轮退货诉求和原因，展示确认卡片。
3. 点击“确认执行” → 提交退货申请。提交不代表退款到账或退货资格已获批准。

另一个例子：`查订单 ORD10003` → `那就取消它` → 点击确认。最后一步之前不会修改订单。

配置生成模型后，还可以在同一对话中陈述姓名、商品偏好，再用“还记得我的名字吗”等追问验证历史输入。离线模式支持确定性的订单指代、补充信息和业务结果，不模拟任意自然语言记忆问答。

## 每轮数据流

1. 图外先限流，再检查原始输入护栏；命中护栏立即拒答，不打开数据库会话或恢复记忆。
2. 校验会话归属和确认凭证，在事务内恢复近期原文、摘要与业务上下文；将超过窗口或预算的旧消息增量汇总，保存摘要和已处理消息游标。
3. 在图外结合当前原话解析订单指代、补充信息和未完成诉求，得到本轮解析结果，然后构造完整的 `AgentState`。
4. LangGraph 从 `classify_intent` 开始，共 9 个业务节点：`classify_intent`、`route_complexity`、`retrieve_docs`、`plan_tasks`、`execute_tools`、`generate_answer`、`refuse_answer`、`check_faithfulness`、`compact_memory`。意图识别、规划、回答获得预算内的历史；路由与检索使用补全后的问题。
5. 写操作只形成不可变提案；用户携带有效确认 ID 后才执行。历史中的“同意”或摘要不提供执行权限。`compact_memory` 仍在图内，负责整理本轮问答与业务上下文。
6. 图外将本轮原文、回答、引用、准备阶段状态、实际图节点记录、记忆上下文和提案状态与业务写入一并持久化、提交，再返回响应。JSON 与 SSE 共用同一处理流程；SSE `stage` 事件实时报告图外阶段的开始、完成或失败，`node` 事件只记录实际完成的图内节点。准备阶段的进度与节点计数分开展示。

窗口默认保留最近 20 条消息（包括用户和助手），会话记忆预算默认 6000 Token，摘要存储上限默认 4000 字符。当前 Token 估算使用字符启发式，并保守限制输入字符数。摘要是有损压缩，不是无限逐字记忆；业务当前状态仍以本轮工具查询为准。

```dotenv
MEMORY_RECENT_MESSAGES=20
MEMORY_CONTEXT_TOKENS=6000
MEMORY_SUMMARY_MAX_CHARS=4000
```

摘要服务不可用时使用有界原文合并降级，不会直接丢弃已有摘要。旧版会话首次恢复时会根据已有用户消息补建结构化上下文。

## 存储与升级

原有 `sessions`、`messages` 保存会话和原文。新增：

| 表 | 内容 |
|---|---|
| `conversation_memory` | 当前订单、未完成诉求、摘要游标、显式清空记忆的消息边界 |
| `pending_actions` | 确认提案、所属用户/会话、有效期和处理状态 |
| `message_metadata` | 回答引用、图外准备阶段状态、图内节点进度和提案元数据，用于历史恢复 |

本地 SQLite 启动会添加缺失的新表，并兼容修复早期 `conversation_memory` 表缺少 `forgotten_message_id` 的情况：补充 `INTEGER NOT NULL DEFAULT 0` 列，保留已有上下文、摘要游标和消息。建表与补列在启动写锁内执行，可以重复运行。使用迁移管理的部署可运行 `alembic upgrade head`；`0003_conversation_memory.py` 创建记忆表，`0004_memory_forgetting_cursor.py` 兼容修复早期缺列版本。无需增加外部记忆服务或依赖。

同一会话的读写通过事务内的会话写锁序列化；SQLite 的数据库写锁也会串行化不同会话的写事务。多用户并发部署宜使用 PostgreSQL。当前只校验传入 `user_id` 与会话所有者一致，可信登录认证仍应由部署的认证层实现。

## 重启与确认

确认提案在数据库中保留 15 分钟，重启或不同服务进程可以继续读取。只允许在原用户、原会话确认；取消、过期或被新提案替代后拒绝执行。已经成功执行的确认重试复用幂等结果，避免重复写入。

开发环境默认每次启动恢复演示订单，因此会作废关联的旧确认卡片与未完成操作，保留历史文字。要演示“重启后继续之前的待处理操作”，先设置 `RESET_DEMO_ON_STARTUP=false`；普通聊天记录、摘要和会话仍会保留。

## 查看、清空与删除

浏览器按用户缓存并同步服务端会话。换浏览器后，用同一身份连接同一后端即可恢复列表；选择会话时恢复最近 100 条消息及引用、节点进度和有效卡片。更早消息可通过历史 API 分页查询。

右上角橡皮擦清空当前会话记忆，保留历史显示；服务端记录清空边界，之后不会再把边界前的原文重新摘要或用于模型输入。侧栏删除会话会删除聊天原文、摘要、结构化上下文及提案，不回滚业务订单。接口见 [API 参考](06-api-reference.md#会话历史与记忆)。
